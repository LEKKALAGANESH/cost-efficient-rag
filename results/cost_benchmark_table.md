# Cost Benchmark: Embedded vs Managed Vector Store

Generated by `eval/cost_analysis.py`. Query volume: **50,000/month**. Vectors are 384-dim float32.

Managed figures are illustrative list prices captured 2026-07 and must be re-verified against vendor pricing pages before being quoted. Every number below traces to a labelled constant at the top of `eval/cost_analysis.py`.

## Assumptions

| Assumption | Value | Basis |
|---|---|---|
| Embedding dimension | 384 | all-MiniLM-L6-v2 model card |
| Bytes per dimension | 4 | IEEE-754 float32 |
| Vector bytes | 1,536 B | 384 x 4 |
| Metadata bytes/vector | 700 B | ids, source, file_type, chunk text |
| Total per vector | ~2,236 B (~2 KB) | computed |
| Query volume | 50,000/mo | 'large but lightly queried' premise (0.0193 QPS) |
| Embedded storage | $0.08/GB-mo | AWS EBS gp3 (attached disk) |
| Backup storage | $0.023/GB-mo | AWS S3 Standard |
| Embedded marginal compute | $0 / ~$12 / ~$35-85 per month | **scale-dependent, not $0** - see below |
| Serverless floor | $50.00/mo | max(usage, floor), NOT floor + usage |
| Serverless read units | $8.25/1M RU | 1 RU per GB scanned, 0.25 RU floor |
| Provisioned RAM | $57.0/GB-mo | resource-hour billing x1.6 index overhead |

### Why marginal compute is not $0

This is the single most attackable line in any embedded-vs-managed comparison, so it is stated explicitly rather than assumed away.

CPU genuinely is free at this volume: 50,000/month is 0.0193 QPS, and an embedding pass plus an ANN probe at that rate is a rounding error on any host. **RAM is not free.** An embedded store's residency cost is memory, and it does not vanish because the process is shared with the API. At 10M vectors the IVF-PQ codes wanting page-cache residency, refine reads into the 15 GB raw vector column, the embedding model's own ~0.8-1.2 GB resident set, and Lance's default 2 GB read buffer together move the host from a 2 GiB instance (~$12/mo) to an 8-16 GiB one (~$49-98/mo).

## Fully-loaded monthly comparison

The embedded row includes compute and backup, not just disk. Comparing a managed all-in price against an embedded storage-only price is the apples-to-oranges error this table exists to avoid.

| Scale | Embedded (fully loaded) | Serverless usage-based | Provisioned resource-hour | Activity-unit tier |
|---|---|---|---|---|
| 100,000 | **$0.08** | $50.00 ($0 on free tier) | $3.27 | $45.00 |
| 1,000,000 | **$12.21** | $50.00 | $32.67 | $80.00 |
| 10,000,000 | **$37.14 - $87.14** | $50.00 | $326.68 | $300.00 |

### Headline result

At 10M vectors the embedded store costs $37.14-$87.14/month fully loaded, against $326.68 for provisioned resource-hour billing and $300.00 for the activity-unit tier - a **3.7x to 9x** saving against provisioned capacity, because you never pay for idle RAM you did not request.

That figure models the managed side the way it is actually deployed: int8 scalar quantization (~4x smaller vectors, the default on these services) with the text payload on disk rather than in RAM. Assume neither -- raw float32 resident, payload billed at RAM rates -- and the same arithmetic returns $1,305.15/month and a 20x+ headline. That is an upper bound, not a quote, and inflating the denominator is the easiest way to make this comparison look better than it is.

Against **serverless usage-based** pricing at this query volume it is roughly a wash ($37.14-$87.14 vs $50.00), and below the 2.0 GB free-tier cap the managed option is outright cheaper. There the win is operational - no vendor, no egress metering, no data-residency question - not economic.

A table showing the embedded store 100x cheaper everywhere with no caveats would be less credible, not more.

## Sensitivity: how query volume changes the answer (at 10M vectors)

| Queries/month | Embedded | Serverless | Verdict |
|---|---|---|---|
| 50,000 (1x) | $37.14 - $87.14 | $50.00 | roughly a wash |
| 500,000 (10x) | $37.14 - $87.14 | $92.77 | embedded ~1.1x cheaper |
| 5,000,000 (100x) | $74.28 - $174.28 | $865.88 | embedded ~5.0x cheaper |

Two notes. (1) Against usage-based pricing the embedded advantage **grows** with query volume, which is the opposite of the intuition that managed wins at scale. (2) gp3's 3,000-IOPS free baseline is not binding at 50K/month (~2 IOPS) but becomes binding near 100x, where the embedded row doubles for extra vCPU and provisioned IOPS - which is why it is not modelled as flat.

## What the embedded row does not include

- **Multi-region replication and automatic failover.** A managed floor price buys operational simplicity the embedded path does not have out of the box.
- **Index build capacity.** At 10M the IVF k-means training sample alone is ~1.24 GB before the streaming write phase, realistically wanting 8-16 GiB and several hours. A single-box architecture has no offline build path.
- **Compaction.** Every Lance write creates a version; without a scheduled `optimize()` and index cleanup, disk grows without bound. An architecture gap as much as a cost one.
- **Write serialisation.** Optimistic concurrency means multi-process ingestion wants an explicit lock or a dedicated worker.
- Backup **is** included above ($0.48/mo at 10M, 29% of the storage line it footnotes - quantified rather than waved at).

**One-time embedding cost avoided.** Local MiniLM inference is $0 (2-6 hours of CPU at 10M chunks). A paid embedding API at 125 tokens/chunk would be a one-time **$25.00** at 10M - roughly 15 months of the storage bill in a single pass. Worth modelling precisely because the local choice avoids it.

## When to switch back to managed

Switch when **any one** holds:

1. The corpus exceeds what a single node can index and hold in its working set.
2. Multi-region HA or a compliance guarantee is required that would otherwise need bespoke engineering.
3. Write concurrency from multiple independent services exceeds what a single-writer ingestion path can absorb.

Query volume is deliberately **not** on that list - per the sensitivity table it favours staying embedded.
